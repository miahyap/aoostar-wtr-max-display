# aoostar-lcd — Unraid plugin for the AOOSTAR WTR MAX integrated display

Drives the WTR MAX (and GEM12+ PRO) case LCD on Unraid using the
open-source, reverse-engineered [aoostar-rs](https://github.com/zehnm/aoostar-rs)
driver — **no vendor software required**. Two small Rust binaries
(~17 MB total, running from RAM):

- **`aster-sysinfo`** — collects CPU / memory / network / temperature /
  disk sensors into a text file in tmpfs every few seconds
- **`asterctl`** — renders a sensor panel (AOOSTAR-X theme format) and
  pushes it to the LCD over its USB serial port (USB ID `0416:90a1`)

The plugin wires them into Unraid properly:

- Starts at boot (independent of the array — nothing touches `/mnt`)
- Settings page under *Settings → Utilities → AOOSTAR LCD*: status,
  start/stop, display on/off, sensor listing, and options (autostart,
  a daily off/on schedule, network interface, refresh intervals,
  smartctl on/off)
- Panel config and sensor mapping persist on the flash drive at
  `/boot/config/plugins/aoostar-lcd/cfg/`
- The asterctl release tarball is cached on flash, so reboots reinstall
  fully offline
- Disk-friendly defaults: smartctl temperature polling is **off**
  (it would wake spun-down disks) and disk usage refresh is 30 min

## Install

### From the web UI, by URL (simplest)

**Plugins → Install Plugin**, paste, **Install**:

```
https://raw.githubusercontent.com/miahyap/aoostar-wtr-max-display/main/unraid-plugin/aoostar-lcd.plg
```

This needs internet access on first start so `rc.aoostar-lcd` can fetch and
checksum-verify the asterctl tarball; it is cached on flash afterwards. Skip
to step 3 below once it finishes.

### From flash (works fully offline)

1. Copy the plugin (and optionally the verified driver tarball for a
   fully offline install) to the Unraid flash drive:

   ```sh
   scp aoostar-lcd.plg root@tower:/boot/config/plugins/
   # optional but recommended (skips the GitHub download):
   ssh root@tower mkdir -p /boot/config/plugins/aoostar-lcd/packages
   scp asterctl-v0.2.0-6-g2f4d959-Linux-x64.tar.gz \
       root@tower:/boot/config/plugins/aoostar-lcd/packages/
   ```

   (replace `tower` with your server's hostname/IP)

2. Install it — either in the web UI via **Plugins → Install Plugin**,
   entering `/boot/config/plugins/aoostar-lcd.plg`, or over SSH:

   ```sh
   plugin install /boot/config/plugins/aoostar-lcd.plg
   ```

   The display should light up with the default sensor panel within a few
   seconds.

3. Optional: open **Settings → Utilities → AOOSTAR LCD** to pick the
   network interface shown (default `auto` = the interface of the default
   route, `br0` on a stock Unraid), then *Apply*.

4. Optional: install the **IT87 Driver** plugin (by ich777) from the Apps
   tab for fan-RPM / extra motherboard sensors.

## Customizing what the display shows

- Panel layout: `/boot/config/plugins/aoostar-lcd/cfg/monitor.json`
  (same format as official AOOSTAR-X themes, including background
  images in the same folder). Restart the driver after editing.
- Sensor mapping: `/boot/config/plugins/aoostar-lcd/cfg/sensor-mapping.cfg`
  maps panel labels to your hardware's sensor names. It is auto-generated;
  delete its first line to take manual control. Use the
  *Show available sensors* button on the settings page to list everything
  your system reports (including per-NVMe temperatures to map to the
  SSD slots on the panel).

## Why not the official AOOSTAR-X binary?

The vendor's Linux build does run on Unraid (their own readme describes a
User Scripts workaround), but it is a 182 MB closed-source PyInstaller
blob, runs a web server on port 5123 with default credentials, and has a
built-in expiration mechanism. The aoostar-rs driver is ~17 MB, open
source (MIT/Apache-2.0), and has no service/UI baggage — a much better
fit for a headless NAS. The vendor package is kept in
`../WTR MAX+GEM12+ PRO Screen Software/` as a reference/fallback.

## The "Unraid Dark" panel

The plugin ships its own panel (generated by `src/make_panel.py`) instead
of the vendor theme:

- **Four stat tiles** across the top — CPU %, GPU %, die temperature and
  RAM % — each a caption over one large value, colored green/amber/red by
  thresholds (CPU/GPU 70/90 %, RAM 80/92 %, temperature configurable).
  Colors work via triple label "slots" — `unraid-stats.sh` writes each
  value under exactly one of `_g`/`_a`/`_r` and asterctl skips labels with
  no value.
- **Network**, one row per direction: arrow, current speed, a
  **history sparkline** and the window peak (block-element graphs on a square-root scale
  relative to the window peak, so light traffic stays visible next to a
  burst; window length configurable, default 15 min). Speeds are read from
  the kernel's own counters in `/sys/class/net`, because aster-sysinfo only
  reports physical NICs — not `br0`/`bond0`. A missing or unplugged
  interface is named on the panel (`eth3 link down`) instead of showing a
  misleading `0 B/s`.
- **Bottom strip**: green disk summary (hottest HDD / SSD, standby count,
  array usage) with the IP address and a clock on the right; switches to a
  red alert naming the disks at/over their threshold (up to three, the rest
  counted). Temperatures and sizes come from Unraid's own `disks.ini`, so
  spun-down disks are never woken.

The design targets the panel as it really looks — poor black level and a
narrow gamut off-axis — so the background is pure black, status colors are
saturated, and nothing is smaller than 20 px.

`unraid-stats.sh` is covered by `src/test/test_stats.sh`, which runs it
against mock `/sys`, `/proc` and `disks.ini` trees in a Linux container
(interface selection, rates from counter deltas, dead-interface reporting,
history bucketing, sparkline scale, disk summary):

```sh
docker run --rm -v "$PWD":/w -w /w bash:5.2 bash unraid-plugin/src/test/test_stats.sh
```

The collector folds network samples into a fixed number of time buckets as
they arrive, so its cost per cycle does not grow with the graph window, and
its loop uses bash builtins only (no `awk`/`cat` forks). Note: asterctl's sensor
map never drops keys, so the collector rewrites every label each cycle
(empty = render nothing) - relying on absent keys causes stale overlaps.
**Text placement.** asterctl does not treat a text sensor's `y` as its top
edge: it offsets the line by two thirds of the *tallest glyph in the string*.
The first panel ignored that, so on the device captions straddled zone
borders and an idle (all-baseline) sparkline dropped onto the row below.
`make_panel.py` now positions everything by baseline with the tallest glyph
class declared per sensor, and the collector keeps that class stable (every
sparkline starts with a full-height axis glyph; a dead link shows `n/a`, not
dashes). `src/test/test_panel.py` renders the panel with asterctl's own
simulator (`--simulate --save`, in a Docker container, no hardware) and
checks that every sensor's ink stays inside its zone and that none collide,
across typical, widest-value, link-down and disk-alert scenarios:

```sh
python3 unraid-plugin/src/test/test_panel.py --keep /tmp/panel-frames
```

Colors and legibility still need a look at the real display. To customize, edit
`/boot/config/plugins/aoostar-lcd/cfg/monitor.json` and restart the driver
(once customized, the plugin never overwrites it; delete it to return to
stock). Prefer changing `make_panel.py` and regenerating for anything you
want to keep — a hand-edited `monitor.json` is not the source of truth.
